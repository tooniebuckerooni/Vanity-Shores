Level 2, and the jump to Sierra 72

A build order for whoever takes Level 2. Read it top to bottom: the three steps are in dependency order, and doing them out of order costs a rewrite. Everything here about Level 1 was read out of the shipping build by node tools/canon.js — if a number below disagrees with docs/game-bible.html, the bible is right and this is stale.

Step 1 — the split done

This is finished. It is written up rather than deleted because the shape it left behind is the shape Level 2 has to fit into.

The game is index.html plus js/*.js, loaded as plain classic scripts in dependency order — not modules, because ES modules fail on file:// and the page has to open straight off a disk. They share one global scope exactly as the single file did, so load order still matters: a file that runs at load time cannot reference a const declared in a later one.

filelineswhat is in it
js/core.js48palette, canvas, render target, helpers
js/cast.js899the procedural cast — setCharHeight lives here
js/text.js541-bit thresholded webfont type
js/scenery.js428backdrops, props, baked room layers
js/audio.js241the adaptive score
js/engine.js446state, money, items, movement, interface, dispatch
js/level1.js1342Level 1 content — the shape your file copies
js/shell.js569front of house, input, loop, boot() — must load last

Adding Level 2 is three things

  • Write js/level2.js. Copy the shape of js/level1.js: the cast entries, the rooms, the scripted scenes. Nothing outside your file needs editing for content.
  • Add one <script src> to index.html, after level1.js and before shell.js. Put it after and boot runs before your rooms exist.
  • Add it to sources in tools/vanity-shores.canon.js.
That third one is the trap, and it fails silently. Canon's probe drives the live page, so every runtime table stays correct and nothing errors. But the scanner reads text — miss the entry and your whole level counts as zero words with every scene reported unclaimed, while the bible looks perfectly healthy. tools/canon/index.js now refuses to start if a declared source is missing, but it cannot know about a file you never declared. Check by running node tools/canon.js and confirming your characters appear in the load table with non-zero word counts.

The split itself was verified this way and is worth repeating for any structural change: word counts, branch counts, load scores, flag count, scene count and gate count were byte-identical before and after. If a refactor moves code, that comparison is the proof it moved nothing else.

Step 2 — Sierra 72

The renderer is already ready. Every proportion in charMetrics is a fraction of CHAR_H, so setCharHeight(72) resizes the buffers and clears the sprite cache on its own. Outfits paint inside a clip of the torso path, so all ten inherit the new silhouette for free. The marks were deliberately sized as fractions of head height for this.

What is free

  • Every character, every outfit, every hairstyle. One call.
  • The anatomy that could not survive at 40px starts working. The hourglass waist is painted as a dark wedge inside the torso clip because a 1px keyline closes any gap under about 3px. At 72 the geometry can carry it — and the marks stop being 1px hints.
  • Portraits and closeups. Separate buffers at PW×PH, unaffected.

What costs real work — the four backdrops

Props and walk bands are composed for a 40px cast. At 72 a figure is 1.8× taller and the sprite buffer goes from 74px to 134px, which is most of a 200px-tall screen.

That head-height column is the problem in one number. A 72px figure standing on the back line of arrival puts its head at y=62 — up in the skyline, well above the horizon the backdrop was painted for. Each room needs the walk band moved down, the horizon raised, or both, and the props re-proportioned to match. Approach points and hotspot rectangles move with them.

Cheapest way to see the damage before committing to it: open the game, run setCharHeight(72) in the console, and walk all four rooms. Nothing will crash — it will just look wrong, specifically and legibly, and that tells you the order to fix things in. Do that before writing any content.

Level 1 is not being re-cut to 72. It ships at 40 and stays there. If the mixed scale reads badly across the level boundary, that is a product decision for the lead, not something to solve by quietly rescaling a shipped, tagged, tested level.

Step 3 — the spine, and what does not carry itself

All 25 of Level 1's flags currently read as live. Level 1 consumes everything it writes. That means nothing propagates to Level 2 automatically — there is no inheritance mechanism, only flags sitting in the save that a later level has to deliberately read. Canon reports a flag written and never read as awaiting-payoff, which is a note rather than an error precisely so this stays visible.

Level 2 — Other People's Money

Chip stops mocking and starts competing. Reuse arrival, boardwalk, pier and underpier; add one or two locations — the wall, then the Kingfisher. The room, hotspot and dialogue shapes are all data, so a new level is mostly content.

  • The win line must be a person, not a number. This is Level 1's hardest-won lesson. The level used to end when the purse crossed $100 and it was inert; it ends on a confrontation now and it lands. Money is the ticket, never the trophy.
  • The want has escalated, it has not matured. Act 1 was revenge on the class of people who flick quarters. Act 2 is wanting to be seen — plus appetite. The character is not learning better, they are getting more of what they came for and enjoying it. Do not write Level 2 as the beginning of a redemption.
  • Sex is per-character, and Level 2 is not where it wins. Easter-egg tier and special items here. A level that is won by getting laid is Level 4 or 5. Occasionally it should be a bad idea and kill you — that is also later, not here.
  • Adult content stages off-screen in a cutaway. Funnier, cheaper, and it keeps the build shippable without an age gate. See brendaSecret for the pattern: the vignette reads GS.cut.i so the page sets the tempo.
  • Deaths cost a quarter of the purse. Any new death must leave the player able to climb out. --check enforces it.

What fails the build

These are not style notes. node tools/canon.js --check exits non-zero on all of them and the deploy runs it on every push.

  • Every scene declares its owner at the declaration. function chipBeat(){ /* @owner chip */. Narration belonging to no character is @owner system. An untagged scene is reported as unclaimed rather than skipped — a loud gap beats a silent miscount.
  • A beat the player must get past is @critical, and it fails the build if every one of its choices ends up behind a stat gate. An even split clears nothing.
  • Money is in cents. ECONOMY and GATES are the single source of truth. Nothing hard-codes a figure or a threshold.
  • Set flags when they are earned, never in a then callback. A then fires on dismissal and can be lost to a room transition.
  • Regenerate the bible with node tools/canon.js after any change to a location, character, payout or gate. Never hand-edit docs/game-bible.html.
  • Run node tools/canon-test.js. 17 checks against a fixture with defects planted on purpose. A checker that has quietly stopped checking also reports a clean bill of health.
  • Wait on game state, never on the clock. Every false test failure this project has had came from a fixed delay. Dialogue choices only become selectable on the final view of the final page, and room transitions take about 600ms of fade.
